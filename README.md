# UI-автотесты «Первого Гипермаркета Мебели»

## Подготовка

Для запуска нужны Node.js с npm, Git Bash и установленный Google Chrome. Открой Git Bash в корне проекта и установи зависимости.

```bash
npm ci
```

## Запуск тестов

| Что запустить | Команда |
| --- | --- |
| Прогон по умолчанию | `bash run.sh` |
| Полный прогон с отправкой SMS и оформлением заказа | `bash run.sh --include-live` |
| Все сценарии входа по паролю | `bash run.sh autotest/auth/password-signin.spec.ts` |
| Только вход по e-mail | `bash run.sh -g 'Вход по e-mail'` |
| Вход по e-mail в Playwright Inspector | `bash run.sh -g 'Вход по e-mail' --debug` |
| ТК-ВХ-13 без запроса учётных данных | `bash run.sh --no-prompt -g 'ТК-ВХ-13'` |
| ТК-ВХ-13 с видимым окном Chrome | `bash run.sh --no-prompt -g 'ТК-ВХ-13' --headed` |
| Список тестов без запуска | `bash run.sh --list` |
| Справка по скрипту | `bash run.sh --help` |

Без `--headed` и `--debug` Chrome запускается без видимого окна. Скрипт передаёт флаги Playwright, например `-g`, `--headed` и `--debug`, напрямую.

### Тесты, которые по умолчанию пропускаются

При `bash run.sh` два теста отмечаются как пропущенные. Флаг `--include-live` включает оба. Каждый из них можно запустить отдельно.

| Тест | Что делает | Отдельный запуск |
| --- | --- | --- |
| ТК-ВХ-02 | Отправляет одно SMS на тестовый `PHONE` и вводит случайный код | `RUN_LIVE_SMS=1 bash run.sh -g 'ТК-ВХ-02'` |
| ТК-КП-21 | Оформляет заказ с оплатой в магазине и отменяет его после проверки | `RUN_LIVE_ORDER=1 bash run.sh -g 'ТК-КП-21'` |

Флаг можно сочетать с фильтром, например `bash run.sh --include-live -g 'ТК-ВХ-02'`. При включённой отправке SMS или оформлении заказа тесты по умолчанию идут последовательно. При `RUN_ORDER_PREVIEW=1` сценарий ТК-КП-21 останавливается перед созданием заказа даже с `--include-live`.

Перед отправкой SMS сайт запускает SmartCaptcha. Если появляется окно с заданием, ТК-ВХ-02 отмечается в отчёте как `skipped` с указанием причины. Если появляется поле SMS-кода, тест продолжает проверку. Ошибка отправки или тайм-аут по-прежнему приводят к падению с диагностикой без номера телефона и кода.

## Учётные данные

`run.sh` запрашивает телефон, e-mail, пароль и имя с фамилией в терминале. Ввод скрыт, файл `.env` для запуска через скрипт не нужен. Если переменная `PHONE`, `EMAIL`, `PASSWORD` или `CUSTOMER_NAME` уже задана в окружении, скрипт использует её. Поле, которое не нужно выбранному тесту, можно пропустить клавишей Enter.

Для обоих вариантов ТК-ВХ-09 используй телефон и e-mail одной учётной записи с действующим паролем. В `CUSTOMER_NAME` передай имя и фамилию в том порядке, в котором они показаны в меню профиля. Для прогона с реальным паролем не добавляй `--trace on`.

## Покрытие входа

В наборе 9 проверок. ТК-ВХ-09 и ТК-ВХ-12 дают по два независимо запускаемых варианта. Для парольного входа проверяются телефон и e-mail, пустой логин и пароль, неизвестный аккаунт и неверный пароль. Поле логина принимает произвольное непустое значение, поэтому отдельной проверки ошибки формата нет.

ТК-ВХ-13 проверяет переключение согласия, ТК-ВХ-14 — блокировку запроса SMS без согласия. Повторный запрос SMS по ТК-ВХ-04 исключён из автопрогона. Вход с действительным SMS-кодом, срок действия кода, VK ID и установка пароля пока не покрыты.

## ТК-КП-21

Для оформления нужен отдельный тестовый аккаунт с пустой корзиной, сохранёнными ФИО и подтверждённым телефоном. Передай `EMAIL` и `PASSWORD` через окружение или скрытый ввод скрипта. Используй аккаунт только для одного прогона одновременно.

```bash
RUN_LIVE_ORDER=1 bash run.sh -g 'ТК-КП-21'
RUN_ORDER_PREVIEW=1 bash run.sh -g 'ТК-КП-21'
```

Сценарий выбирает первый диван после фильтра «В наличии», проверяет корзину, получателя, пункт выдачи и итог. «Перейти к оплате» создаёт заказ. Тест выбирает только «Оплата в магазине», завершает оформление и сверяет номер, состав, получение и сумму в «Моих заказах». При завершении или падении сценария отдельный шаг отменяет созданный заказ и проверяет, что он исчез из активных. Для отмены тест выбирает «Не подошёл товар» или «Другое». Сайт может сохранить заказ в архиве. Если отмена недоступна или заказ нельзя однозначно определить, шаг очистки завершится ошибкой.

Предпросмотр имеет приоритет, если выставлены обе переменные. Он останавливается перед «Перейти к оплате», очищает корзину и отмечает сценарий как пропущенный. При запуске без этих переменных сценарий пропускается до входа в аккаунт.

## Настройки запуска

По умолчанию используются адрес `https://hypermarketmebel.ru/` и установленный Chrome. Адрес можно задать через `BASE_URL`, канал браузера — через `BROWSER_CHANNEL`. Настройки и их значения по умолчанию собраны в `core/settings.ts`. `PLAYWRIGHT_ENV_FILE` переопределяет путь к локальному файлу переменных, по умолчанию это `.env`.

| Тайм-ауты в миллисекундах | Переменные |
| --- | --- |
| Тест и проверки | `TEST_TIMEOUT_MS`, `EXPECT_TIMEOUT_MS` |
| Действия и навигация | `ACTION_TIMEOUT_MS`, `NAVIGATION_TIMEOUT_MS` |
| Открытие формы, ожидание после клика и ответ авторизации | `AUTH_FORM_TIMEOUT_MS`, `AUTH_OPEN_RETRY_MS`, `AUTH_RESPONSE_TIMEOUT_MS` |
| Запрос SMS и длительность SMS-теста | `SMS_REQUEST_TIMEOUT_MS`, `SMS_TEST_TIMEOUT_MS` |
| Оформление, загрузка данных получателя и истории заказов, очистка | `ORDER_TEST_TIMEOUT_MS`, `ORDER_SYNC_TIMEOUT_MS`, `ORDER_CLEANUP_TIMEOUT_MS` |
| Снимок при падении | `SCREENSHOT_TIMEOUT_MS` |

## Логи и отчёт Allure

Локально Pino по умолчанию выводит время, цветной уровень и сообщение, а дополнительные поля печатает на отдельных строках. Уровень по умолчанию — `info`. Установи `LOG_LEVEL` в `debug`, `info`, `warn` или `error`, чтобы изменить детализацию.

`LOG_FORMAT=pretty` включает терминальный формат. Если Git Bash не распознал поддержку цвета, добавь к команде `FORCE_COLOR=1`. `NO_COLOR=1` отключает цвета. `LOG_FORMAT=json-pretty` печатает отдельные JSON-объекты с отступами. `LOG_FORMAT=json` печатает один объект на строку, этот формат используется по умолчанию при заданной переменной `CI`.

```bash
LOG_LEVEL=debug bash run.sh --no-prompt -g 'ТК-ВХ-13'
npm run report:generate
npm run report:open
```

Результаты последнего прогона лежат в `test-results/allure-results/`. Команда генерации сохраняет HTML-отчёт в `allure-report/`. В отчёте есть ID кейса, статус, шаги, безопасные названия вариантов и диагностика падения. При падении добавляется замаскированный скриншот или причина, по которой его не удалось снять.

Для новых сценариев импортируй `test` и `expect` из `core/test.ts` и оформляй основные действия через `test.step()`. Индивидуальные селекторы чувствительных областей добавляй в `ui/sensitive-regions.ts`. В название теста, шага или параметра передавай описание варианта, например «Вход по e-mail». Для передачи отчёта используй `allure-report/` или очищенные результаты из `test-results/allure-results/`.
