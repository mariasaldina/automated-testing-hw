# UI-автотесты «Первого Гипермаркета Мебели»

## Подготовка

Для запуска требуются Node.js с npm, Git Bash и установленный Google Chrome. Команды выполняются в Git Bash из корня проекта. Зависимости устанавливаются командой `npm ci`.

```bash
npm ci
```

## Запуск тестов

| Режим запуска | Команда |
| --- | --- |
| Прогон по умолчанию | `bash run.sh` |
| Полный прогон с отправкой SMS и оформлением заказа | `bash run.sh --include-live` |
| Все сценарии входа по паролю | `bash run.sh autotest/auth/password-signin.spec.ts` |
| Только вход по e-mail | `bash run.sh -g 'Вход по e-mail'` |
| Вход по e-mail в Playwright Inspector | `bash run.sh -g 'Вход по e-mail' --debug` |
| ТК-ВХ-13 без запроса учётных данных | `bash run.sh --no-prompt -g 'ТК-ВХ-13'` |
| ТК-ВХ-13 с видимым окном Chrome | `bash run.sh --no-prompt -g 'ТК-ВХ-13' --headed` |
| Список тестов без запуска | `bash run.sh --list` |
| Справка по скрипту | `bash run.sh --help` |

Без `--headed` и `--debug` Chrome запускается без видимого окна. Скрипт передаёт флаги Playwright, например `-g`, `--headed` и `--debug`, напрямую.

### Сценарии с явным включением

При стандартном запуске ТК-ВХ-02 и ТК-КП-21 отмечаются как пропущенные. Флаг `--include-live` включает оба сценария. Для отдельного запуска предусмотрены следующие команды.

| Тест-кейс | Действие на сайте | Отдельный запуск |
| --- | --- | --- |
| ТК-ВХ-02 | Отправляет одно SMS на тестовый `PHONE` и вводит случайный код | `RUN_LIVE_SMS=1 bash run.sh -g 'ТК-ВХ-02'` |
| ТК-КП-21 | Оформляет заказ с оплатой в магазине и отменяет его после проверки | `RUN_LIVE_ORDER=1 bash run.sh -g 'ТК-КП-21'` |

Флаг `--include-live` совместим с фильтром Playwright, например `bash run.sh --include-live -g 'ТК-ВХ-02'`. При включённой отправке SMS или оформлении заказа тесты по умолчанию выполняются последовательно. При `RUN_ORDER_PREVIEW=1` сценарий ТК-КП-21 останавливается перед созданием заказа, в том числе при наличии флага `--include-live`.

Перед отправкой SMS сайт запускает SmartCaptcha. Если появляется окно с заданием, ТК-ВХ-02 отмечается в отчёте как `skipped` с указанием причины. Если появляется поле SMS-кода, тест продолжает проверку. Ошибка отправки или тайм-аут по-прежнему приводят к падению с диагностикой без номера телефона и кода.

## Учётные данные

`run.sh` принимает учётные данные из переменных окружения или через скрытый ввод в терминале. Создание файла `.env` для запуска через скрипт необязательно. Если переменная уже задана в окружении, запрос соответствующего значения пропускается. Для данных, которые не требуются выбранному сценарию, допустим пустой ввод.

| Переменная | Значение |
| --- | --- |
| `PHONE` | Телефон тестовой учётной записи. В ТК-ВХ-02 на этот номер отправляется SMS. |
| `EMAIL` | Адрес электронной почты тестовой учётной записи. Для обоих вариантов ТК-ВХ-09 телефон и e-mail относятся к одной учётной записи. |
| `PASSWORD` | Действующий пароль тестовой учётной записи. |
| `CUSTOMER_NAME` | Имя и фамилия в порядке отображения в меню профиля. |

Трассировка Playwright отключена по умолчанию. При использовании действующих учётных данных трассировка должна оставаться отключённой.

| Тест-кейс | Входные данные или вариант | Проверяемый результат |

| ТК-ВХ-09 | `PHONE`, `PASSWORD`, `CUSTOMER_NAME` | Вход по телефону выполнен. В меню профиля отображаются ожидаемое имя пользователя и пункт «Выход». |
| ТК-ВХ-09 | `EMAIL`, `PASSWORD`, `CUSTOMER_NAME` | Вход по e-mail выполнен. В меню профиля отображаются ожидаемое имя пользователя и пункт «Выход». |
| ТК-ВХ-10 | Сгенерированный e-mail без учётной записи и тестовый пароль | Вход отклонён, отображается сообщение «Неверный логин или пароль», сохраняется гостевая сессия. |
| ТК-ВХ-11 | `PHONE` и заведомо неверный пароль | Вход отклонён, отображается сообщение «Неверный логин или пароль», сохраняется гостевая сессия. |

| ТК-ВХ-12 | `PHONE` и пустой пароль | Вход отклонён, отображается сообщение «Логин или пароль не заполнены», поле пароля выделяется как ошибочное, сохраняется гостевая сессия. |
| ТК-ВХ-13 | Исходное состояние флажка, его установка и снятие | В форме входа отображается текст согласия на обработку персональных данных. Флажок изначально снят и корректно меняет состояние в обе стороны. |
| ТК-ВХ-14 | `PHONE` и снятый флажок согласия | После попытки получить код блок согласия подсвечивается, кнопка остаётся в заблокированном состоянии, форма ввода кода не открывается. |

## Сквозной сценарий ТК-КП-21

Для оформления требуется отдельная тестовая учётная запись с пустой корзиной, сохранёнными ФИО и подтверждённым телефоном. `EMAIL` и `PASSWORD` передаются через переменные окружения или скрытый ввод. Одновременное использование учётной записи в нескольких прогонах исключается.

```bash
RUN_LIVE_ORDER=1 bash run.sh -g 'ТК-КП-21'
RUN_ORDER_PREVIEW=1 bash run.sh -g 'ТК-КП-21'
```

1. Выполняется вход по e-mail и паролю. Проверяется, что корзина пуста.
2. В каталоге применяется фильтр «В наличии». Открывается карточка первого доступного дивана, сверяются название и цена. В корзину добавляется одна единица товара.
3. В корзине сверяются товар, количество, цена и итоговая сумма. После выбора товара открывается форма оформления заказа.
4. Подтверждаются сохранённые контактные данные получателя, выбирается пункт выдачи и отмечается согласие на обработку персональных данных. Фиксируются адрес пункта выдачи и итоговая сумма.
5. При переходе к оплате сайт создаёт заказ. Выбирается способ «Оплата в магазине», завершается оформление и проверяется наличие номера заказа на странице подтверждения.
6. В разделе «Мои заказы» находится новый заказ. Сверяются его номер, состав, количество, итоговая сумма, сведения о получении и адрес пункта выдачи.
7. При завершении или падении сценария созданный тестом заказ отменяется с причиной «Не подошёл товар» или «Другое». Проверяется, что он исчез из активных заказов. При необходимости корзина очищается. Если заказ нельзя однозначно определить или отмена недоступна, шаг очистки завершается ошибкой.

Если заданы обе переменные, приоритет имеет режим предпросмотра. В этом режиме сценарий останавливается перед переходом к оплате, корзина очищается, а тест отмечается как пропущенный. При запуске без этих переменных тест пропускается до авторизации.

## Настройки запуска

По умолчанию используются адрес `https://hypermarketmebel.ru/` и установленный Chrome. Адрес можно задать через `BASE_URL`, канал браузера — через `BROWSER_CHANNEL`. Настройки и их значения по умолчанию собраны в `core/settings.ts`. `PLAYWRIGHT_ENV_FILE` переопределяет путь к локальному файлу переменных, по умолчанию это `.env`.

| Тайм-ауты в миллисекундах | Переменные |
| --- | --- |
| Тест и проверки | `TEST_TIMEOUT_MS`, `EXPECT_TIMEOUT_MS` |
| Действия и навигация | `ACTION_TIMEOUT_MS`, `NAVIGATION_TIMEOUT_MS` |
| Открытие формы, ожидание после клика и ответ авторизации | `AUTH_FORM_TIMEOUT_MS`, `AUTH_OPEN_RETRY_MS`, `AUTH_RESPONSE_TIMEOUT_MS` |
| Запрос SMS и длительность SMS-теста | `SMS_REQUEST_TIMEOUT_MS`, `SMS_TEST_TIMEOUT_MS` |
| Оформление, загрузка данных получателя и истории заказов, очистка | `ORDER_TEST_TIMEOUT_MS`, `ORDER_SYNC_TIMEOUT_MS`, `ORDER_CLEANUP_TIMEOUT_MS` |
| Снимок при падении | `SCREENSHOT_TIMEOUT_MS` |

## Логи и отчёт Allure

При локальном запуске Pino по умолчанию выводит время, уровень и сообщение, а дополнительные поля размещает на отдельных строках. Переменная `LOG_LEVEL` задаёт уровень логирования. Поддерживаются `debug`, `info`, `warn` и `error`. По умолчанию используется `info`.

`LOG_FORMAT=pretty` включает терминальный формат. `LOG_FORMAT=json-pretty` печатает отдельные JSON-объекты с отступами. `LOG_FORMAT=json` печатает один объект на строку, этот формат используется по умолчанию при заданной переменной `CI`.

Pino выводит логи в стандартный поток вывода. Для каждого прогона можно создать отдельный каталог с отметкой времени.

```bash
run_dir="playwright-runs/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$run_dir"
```

Перенаправление `>` сохраняет лог полного прогона в файл. Запросы скрытого ввода учётных данных остаются в терминале.

```bash
LOG_FORMAT=json bash run.sh --include-live > "$run_dir/run.log"
```

Для одновременной записи в файл и вывода в терминал используется `tee`. Настройка `pipefail` сохраняет ненулевой код завершения, если прогон завершился ошибкой.

```bash
(set -o pipefail; LOG_FORMAT=json bash run.sh --include-live | tee "$run_dir/run.log")
```

После завершения требуемого прогона отчёт формируется и открывается следующими командами.

```bash
npm run report:generate
npm run report:open
```

Результаты последнего прогона лежат в `test-results/allure-results/`. Команда генерации сохраняет HTML-отчёт в `allure-report/`. В отчёте есть ID кейса, статус, шаги, безопасные названия вариантов и диагностика падения. При падении добавляется замаскированный скриншот или причина, по которой его не удалось снять.

Общие фикстуры тестов определены в `core/test.ts`. Основные действия оформлены как шаги Playwright через `test.step()`, а селекторы областей, которые маскируются на скриншотах, заданы в `ui/sensitive-regions.ts`. Для передачи отчёта предназначен каталог `allure-report/`.
